<objective>
Fix audit #1 and #2. A copied folder carries `.milo_backup.info` with stale `s3_key`s, so the daemon "moves" the ORIGINAL folder's S3 objects to the copy's keys and deletes the originals; the original is then skipped forever by the mtime cache. And when a move's source object is missing, the move fails every scan and the file is never uploaded.
</objective>
